# Knowledge-update Development Pack V1

This is a new, frozen 40-question development pack. The canonical 500-question V2/R2 datasets have not been overwritten. No PRAGMOS inference logic was changed while preparing this pack.

## Contents And Limits

- 40 authored synthetic questions, covering 24 analyst-defined semantic profiles across all 78 official Knowledge-update questions. These are not official subtype labels.
- 21 counterparts of historically judge-correct official profiles, and 19 counterparts of historically failed profiles. All 15 primary profiles represented among the historical 35 correct answers have a historical-success counterpart in this pack.
- All six unsupported-scope variants: wrong cuisine/category, role, person, location, object and composite activity.
- All records retain their R2 haystack session counts, turn counts, dates and untouched distractor messages. There are 39-55 sessions per record. Earlier and later evidence are distributed across two sessions. Source slots and their adjacent acknowledgements were replaced; obsolete source slots were neutralized. Two missing history slots were restored in existing sessions.
- Session IDs are opaque. The runtime JSON has only the standard LongMemEval fields. It does not contain reference operations, subtypes, official IDs or historical judge labels.
- Reference facts have exact user-turn quote offsets. Numeric/set answers are recomputed from authored facts. This checks internal consistency, not independent semantic equivalence to official questions.

The 21 controls are **profile-based control candidates**, not 21 already-passing synthetic answers. A fresh baseline on these exact inputs is needed to establish actual regression controls. This is deliberately balanced development data, not a proportional sample or an independent test set. A score of 35/40 would be encouraging, not a prediction of 68/78 officially.

The authored relevant paragraphs average approximately 58 words. Official relevant user turns average 53.6 words across Knowledge-update, or 52.2 words for the selected profiles. Similar word counts and preserved long histories do not prove equal semantic difficulty. Some authored clarifications are more explicit than real conversations. Independent review and later frozen-data validation remain necessary.

## Files

- `pragmos_knowledge_update_validation_40_v1.json`: the only dataset to pass to inference.
- `manifest.json`: selection, input hashes, output hashes and validation limitations.
- `evaluation_only/case_audit.json`: facts, quote offsets, reference calculations, minimal answer-span sessions and historical profile lineage. Never pass this file to inference.
- `evaluation_only/coverage_inventory.json`: the full 78-profile inventory, old judge labels and selected-case markers. Never pass this file to inference.
- `FIX_PLAN.md`: code review, exact proposed change boundaries and regression gates. No proposed inference fix has been implemented in this turn.

Both competing history sessions are labeled relevant, consistent with official Knowledge-update histories. Minimal answer-span sessions are recorded separately in the audit. For unsupported questions, the two near-miss sessions document scope discrimination, not positive evidence for an answer.

## Baseline Before Inference Changes

There has been no model run on this pack yet. This command measures the established production path, keeping both the opt-in composable computation and paused Temporal experiment off. Preserve this configuration for the future paired state-resolver comparison. A candidate typed-v4 run would be a separate experiment, not this baseline.

The new JSON contains exactly 40 selected records. `--start-index 0 --limit 40` runs those 40; it does not mean indices 0-39 of the full 500. Selection is recorded in the manifest and evaluation-only audit.

```zsh
CODE="/Users/moitra/.codex/worktrees/lme-evidence-compiler/context"
PROJECT="/Users/moitra/surya/dev_project/context"
PY="$PROJECT/.venv/bin/python"
MODEL="/Users/moitra/surya/dev_project/phi3-gguf/Phi-3-mini-4k-instruct-q4.gguf"
PACK="$CODE/benchmark/longMemEval/synthetic_v2/knowledge_update_40_v1"
DATA="$PACK/pragmos_knowledge_update_validation_40_v1.json"
RUN="$PROJECT/benchmark/longMemEval/synthetic_v2/knowledge_update_40_v1/runs/baseline_production_v1"
NAME="pragmos_ku40_baseline_production_2k_v1"

export MPLCONFIGDIR=/tmp/pragmos-matplotlib
export PYTHONPYCACHEPREFIX=/tmp/pragmos-ku40-pycache
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1

test -x "$PY" && test -f "$MODEL" && test -f "$DATA"
"$PY" -B "$CODE/build_PRAGMOS_knowledge_update_pack.py" \
  --project-root "$PROJECT" --output-dir "$PACK" --check-only

caffeinate -i "$PY" -B -u "$CODE/PRAGMOS_benchmark_LongMemEval.py" \
  --data-file "$DATA" --mode pragmos_context \
  --question-type knowledge-update --start-index 0 --limit 40 \
  --model-path "$MODEL" --n-ctx 2048 --n-threads 8 --n-gpu-layers 40 \
  --seed 42 --max-tokens 64 --temperature 0 --top-p 1 --repeat-penalty 1.1 \
  --pragmos-top-k 6 --pragmos-min-score 0.20 \
  --pragmos-graph-candidates 4 --pragmos-retrieval-pool 24 \
  --pragmos-multisession-graph-candidates 12 --pragmos-max-retrieval-sessions 12 \
  --pragmos-graph-depth 2 --pragmos-graph-evidence 4 \
  --pragmos-session-neighbor-radius 2 --pragmos-session-neighbors 4 \
  --pragmos-answer-context-tokens 2048 \
  --pragmos-chunk-words 160 --pragmos-chunk-overlap-words 32 \
  --pragmos-embedding-batch-size 64 --pragmos-evidence-compiler-mode validated \
  --pragmos-composable-mode off \
  --pragmos-temporal-engine contracts --pragmos-temporal-contract-mode off \
  --flush-every 1 --output-dir "$RUN" --run-name "$NAME" --resume

jq '{processed,avg_token_f1,avg_exact_match,avg_elapsed_seconds}' \
  "$RUN/${NAME}_summary.json"
```

Offline flags require the existing embedding/reranker weights to be cached. Do not silently remove those flags to permit a download if a model is missing; resolve the missing dependency explicitly.

The standard manifest, predictions and trace are produced. The GPT judge should later use this synthetic pack's answers, not the official oracle's different IDs and answers. No API call is needed to create or validate the pack.
